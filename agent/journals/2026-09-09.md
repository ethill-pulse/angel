## Correction — fleet-side LMS
Eric clarified he meant the fleet-side system, not the crypto 3rd-party vendor.

Answer: **ContractManager** (`contractmanager`) — SFIN's stock borrow/loan contract
management service. Jira project prefix `SFINCM`. Central repository for all SBL contracts
(domestic, international, repo, agency) plus intraday activity, mark-to-market, and rate changes.

Ingests Loanet MQ T4 messages, Loanet ATX (marks) and PAO (EOD loans/borrows) files; exposes
ListContracts / GetContract / ListMovements / ListRates / ListMarks; calls CSC API so journals
get booked in the back office. Publishes to kafka (`sfin.cm.loanet_contract.out`,
`sfin.cm.wab_rates.out` — WAB rates consumed by rates-manager).

Per the "Stock Loans and Borrows" design, functionality was deliberately NOT overloaded into
one contractmanager. Per-business services fan out around it:
- CM API — single front door for all contract API calls from the UI
- US SL CM — US stock loan contracts from Loanet
- SFT — SFT contracts from Broadridge; EOD outstanding loans + MRO marks from DTCC
- Repo — Repo contracts from 4Sight
- US SL Proxy / SFT Proxy / CSC Proxy (`sfincscsproxy`) — venue + CSC connectivity
- `internal-contract-manager` (ICM), split into `agora-contract-manager` for the Agora flow
- `international-stock-loan` — src/constitution/services/international-stock-loan
- `digital-asset-contract-manager` — SFIN service automating Haruko→BK loan create +
  collateral add/return (this is the bridge to the crypto side / Haruko)

Sources: Contract Manager design (SFIN 4.12.3 Proposals), Stock Loans and Borrows design,
Contract Proxy design, various Release Schedule entries.

## What is Olympus
Clear Street's **unified Financing and Treasury Platform** — owned by SFIN (Securities Finance
Engineering). Jira prefix `SFINOL`. React frontend in fleet (`olympus/src/...`, migrated CRA→Vite),
deployed as `docker.co.clearstreet.io/apps/olympus` + `olympus-proxy`. Envs:
dev-olympus.co.clearstreet.io, olympus-uat.clearstreet.io.

Business lines it covers:
- Equity Finance: Locates for Active Traders (Q4 2022), Prime Finance/Demand Desk (Q1 2023),
  US Stock Loan Wholesale (Q1 2024), Arranged Financing/Enhanced Leverage (Q3 2025),
  Managed Lending / "Stock Loan as a Service" (Q4 2025), Portfolio Pricing (Q2 2025),
  US FI Repo (migration ETA Q2/Q3 2026), Market Connectivity & Order Routing (V1 Q1 2025),
  UK/EU Stock Loan + Canada Stock Loan (ETA Q3), Fully Paid Lending (modernization ETA Q4 2026)
- Treasury: Collateral Hub, Margin Forecasting (both Q3 2024), Treasury Cash Management (TCM),
  Collateral Grading, Liquidity & Stress Testing, Banking & Payments (Q3 2025),
  Reserve Capital (ETA Q2 2026), Inventory Attribution (ETA Q3 2026),
  Client Asset Segregation (ETA Q4 2026)
- Regulatory: Supervisory Dashboard (Q3 2024)

Reusable platform components: Inventory Query Engine (real-time position keeping across asset
classes), Olympus Front-End Framework (real-time grids, composable windows, user-defined screens),
in-browser market/ref data near cache, Counterparty Master & Credit Limit Mgmt,
Document Distribution, Identity via Okta→Auth0 (Ory migration in spec),
**Cronus** = the permissioning/RBAC system (column + row level), Data Platform, Public API,
Controls & Auditability.

Relationship to contractmanager: Olympus is the platform/UI + services layer; contractmanager is
the SBL contract store beneath it. Trade lifecycle reads "Olympus via Loanet" for US SL,
"Olympus via Pirum" for UK/EU.

In flight: SFCM → Olympus migration (findings doc 2026-09-01 — Olympus is trade-level, SFCM
splits; recon being rebuilt), Olympus → Ops Portal integration via Kafka, Olympus Migration to
Federated Host (olympusV2 into olympus-suite), Olympus on Ory. Agora (managed SBL) is the first
true SaaS/multi-tenant part of Olympus.

Source: Olympus Platform Overview (SFIN), Olympus Documentation
