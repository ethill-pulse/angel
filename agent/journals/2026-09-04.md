# 2026-09-04

## 22:20
clearstreet-rates-publisher was erroring every 60s for OPENAI-FUNDING (CLST.SPOT.OPENAI-USD) on
2026-08-30/31 — a symbol enabled recently that has no funding data for those dates and never will.
Root cause: `plan_publications` classified every empty window as `SkipReason::NoSettlements` (a
gap), so it logged error-level per (symbol, date), and `run_cycle` returned `skipped.len()` as
`outstanding` — which never reached 0, so `completed_cutoff` was never set and every tick re-drained
both Kafka topics in full, forever.

Fix (working tree, not committed): classify a skip against the symbol's *own* first retained
settlement before asking what the window contains — `NoDataForSymbol` / `BeforeFirstSettlement` /
`PartialFirstWindow` are terminal (info/warn, one line per symbol, not counted as outstanding),
`NoSettlements` stays a real gap (error per pair, holds the cut-off open). Also drops the partial
first day rather than publishing an under-summed rate, which is the existing retention-edge
argument applied per symbol. New stat `rates_publisher.pre_history`. Tests added for new-symbol,
partial-first-window, and mid-history-gap-still-alerts.
