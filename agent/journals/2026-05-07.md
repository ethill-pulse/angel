## ~afternoon — Deribit index price collector research + design

Worked through Deribit REST and WebSocket options for index price data. Context: OTC options settlement requires 30-min TWAP with 4-second sampling of the underlier index price.

**Key findings:**
- Deribit REST offers `get_index_chart_data` (relative ranges only), `get_volatility_index_data` (explicit time range, paginated, 1-min finest resolution), and `get_tradingview_chart_data` (instrument OHLCV, not index). None provide sub-minute resolution.
- `get_index_price_names` returns all 100+ indexes. The relevant subset: 24 `*_usd` indexes excluding stablecoins, DVOL, and drbfix.
- For 4-second resolution data, the only option is the WebSocket feed: `deribit_price_index.{index_name}`, which throttles to ~1 update/second.
- Deribit's own settlement price is published via `get_delivery_prices` — only useful for verifying past settlement, not for forward/OTC use.
- For historical sub-minute data, Tardis is the recommended vendor.
- **Haruko**: already a vendor. Worth asking them directly whether they archive the Deribit index feed as a byproduct of live margin monitoring. They may have it without it being a documented feature.

**WebSocket notes:**
- Subscribe all indexes in a single message with an array of channels.
- Use `(echo '...'; cat) | websocat -t wss://...` to keep stdin open for persistent streaming.
- `COLUMNS=10000` env var set before launching claude to fix copy/paste line-wrap issue.

**Design decisions for the collector service:**
- Standalone service (not integrated into existing market data pipeline) for MVP.
- Future: migrate to normal pipeline, solve Kafka A/B dedup at that time.
- QuestDB table with WAL + `DEDUP UPSERT KEYS(ts, index_name)` handles dual-instance writes cleanly.
- Must use **Deribit-provided `timestamp`** (not local clock) for dedup to work correctly across A/B instances.
- 2 instances run simultaneously for HA; rolling deploys with no data gap.
- 14-day retention to match existing QuestDB policy.
- Index list is config-driven.

GitHub issue drafted covering all of the above. Kept intentionally terse — engineers know the practices.
