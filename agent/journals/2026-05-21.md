## Added pulse/local full-stack FIX runner

Created `repos/pulse/local/` — the new advanced local setup for trade-engine + standalone + polaris (trade-agent). Companion to the simpler `polaris/local/` setup (standalone + trade-agent only).

- standalone runs as RENG FIX acceptor (ports 8999/9000/9001) + sequenced WS channel (8084)
- trade-engine is RENG FIX initiator → standalone, DGTL FIX acceptor for takers (ports 9003/9004/9005 on host)

- kafka + postgres for trade-engine (refdata consumer, markup_tier DB)

## 12:18 — trade-engine startup iteration complete, full stack running

Continued from prior session context. Iteratively fixed all trade-engine startup config errors by adding missing fields to `trade-engine.yml` and `docker-compose.yml`. No Rust code changes were needed.

### Config errors fixed (in sequence)
1. `start_timeout_ms` missing in `kafka_producer` → added
2. `missing kafka_consumer` → added `kafka_consumer:` block with required fields
3. `'enable_auto_commit' is not defined` → added to kafka_consumer
4. `'poll_timeout_ms' is not defined` → added to kafka_consumer
5. `missing error_responses_enabled` → monitoring_server also needs it (not just server)
6. `RefDataManager KafkaConfiguration did not define exactly 1 topic partition` → switched refdata consumer from `topics:` to `topic_partitions:` with partition 0; added seek_behavior, poll_timeout_ms, etc.
7. `SeekBehavior::Beginning` casing → must be `"Beginning"` not `"beginning"`
8. `KafkaError UnknownPartition` → `refdata` topic didn't exist in Kafka; created it manually
9. `ApiKey missing for key-id digital_api_key_md` → secret_key `"X"` fails SecretLookupProvider without passthrough; resolved with file-based secrets
10. `no certificates found in PEM` → DGTL FIX acceptors require TLS; server secret_key must be a combined cert+key PEM
11. `UnsupportedCertVersion` → generated v3 ECDSA cert with SANs; still failed (LibreSSL EC PKCS#8 incompatible with ring)
12. `failed to parse private key as RSA, ECDSA, or EdDSA` → switched to RSA 2048 PKCS#8; worked

### Secret resolution approach (config-only, no code changes)
- Client FIX keys (RENG side): `secret_key: "{{file:/secrets/fix_secret.txt}}"` with `local/secrets/fix_secret.txt` containing `X`
- Server FIX keys (DGTL side): `secret_key: "{{file:/secrets/dgtl_tls.pem}}"` — combined RSA self-signed cert+key PEM generated with `openssl genpkey -algorithm RSA`; mounted into container
- `fix_secret.txt` path uses the `file` provider (already registered in trade-engine main.rs)
